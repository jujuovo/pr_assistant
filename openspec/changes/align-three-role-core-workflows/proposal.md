# Proposal

## Why

第一步已经建立 2028 学业竞赛的材料—审核—自动计分闭环，但项目中仍有大量页面沿用旧 `Application`、可变 `Rule` 和直接编辑成绩的交互假设，后端已经具备的规则版本、排名批次与权限能力也没有形成完整可用的三角色工作台。现在需要让学生、教师、管理员看到并操作同一条后端权威链路，清理会传入冗余业务词条的前端路径，并补齐下一届规则维护和正式排名发布流程。

实施后复核发现，上述“第一步已经建立闭环”只在后端契约和源码外壳层面成立：真实本地环境缺少可用的 current 竞赛规则包，学生竞赛页是不可用的契约壳，既有测试没有挂载 Vue 页面或执行真实浏览器闭环。因此本 change 不得把竞赛前端视为已完成依赖；该缺口由 `repair-2028-competition-workflow-acceptance` 先行修复，本 change 再完成三角色产品级工作台与实际环境验收。

## What Changes

- 新增三角色核心工作台契约：页面完全依据后端状态、`allowed_actions`、版本号和权限范围展示操作，不在前端复制状态机、计分规则或排名规则。
- 学生端统一展示本人材料状态、审核意见、计分解释和排名状态；学生排名只显示本人名次、总人数、本人分数、范围、状态和时间，不提供专业完整名单。
- 教师端统一审核入口与学生汇总视图；教师可查看授权范围内所有学生的材料、项目明细、分数和完整专业排名，但材料事实、规则、分数、排名和冻结状态均只读，仅能通过或退回材料并填写意见。
- 管理员端补齐排名批次操作：按专业生成 draft、查看阻塞项、冻结、发布、撤回/解冻纠错并创建后继版本；每个动作使用版本控制、完整审计和后端事务，不由前端串联多次写请求。
- 管理员端提供“复制上一届规则包—编辑差异—校验预览—发布”为下一届规则的维护流程。2029 届从 2028 正式包复制，草稿可编辑；已发布版本保持不可变，同周期仍只能有一个 current 规则包。
- 规则发布前展示目录、字段、分值、特殊条款差异和影响预览；发布后如影响当前周期已审核材料，继续执行学生重新确认、教师重新审核的既有闭环，不静默改分。
- 清理前端旧契约：竞赛及新工作流页面不再获取或提交 `rule_id`、`self_score`、`final_score`、`dynamic_coefficients`、`override_score`、`override_reason` 等非权威词条；移除本地规则映射、估分、直接改分和直接改排名控件。
- 渐进整理路由、页面与服务层：新链路使用按角色划分的展示组件和单一 API 适配层；尚未迁移的非竞赛材料继续使用旧 `Application` 兼容入口，不在本 change 强行迁移其后端模型。
- 将所有三角色新页面提升为产品级界面，必须具备一致的信息层级、设计系统组件、loading/empty/success/validation/permission/conflict/actionable error 状态和响应式布局。
- 将 mounted component 交互测试与新鲜数据库上的真实浏览器旅程列为完成门槛；生产构建、纯 helper 测试和源码字符串断言不得作为 UI、E2E 或视觉验收的替代品。
- **BREAKING**：旧管理页中的直接编辑综合成绩、专业排名、启停/删除已发布正式规则及教师改分入口不再作为正式业务操作；对应前端能力被移除或改为后端受控命令。
- 范围外：把科研、志愿服务等所有非竞赛类别迁移到 `MaterialRecord`；修改 2028 正式竞赛政策本身；引入微服务、消息队列或由教师执行排名发布。

## Capabilities

### New Capabilities

- `role-workflow-interfaces`: 定义学生、教师和管理员工作台如何依据后端权威状态与权限展示材料、计分、规则和排名，并限制各角色可见信息与可执行动作。

### Modified Capabilities

- `ranking-publication`: 明确管理员生成、冻结、发布和纠错职责，教师完整名单只读权限，以及学生仅查看本人排名结果的具体契约。
- `structured-scoring-rules`: 增加从上一届复制为下一届草稿、差异编辑/校验/发布和历史版本查看的规则包生命周期行为。
- `auditable-scoring`: 收紧管理端对派生综合成绩和排名字段的直接编辑，要求前端只展示权威计分快照并通过受控用例触发重算。

## Impact

- 前端：学生 `Statistics`、材料历史与导航；教师审核、学生汇总和排名页面；管理员规则、成绩与排名页面；路由、stores、API services、状态/错误/权限展示组件。
- 后端：现有规则包复制与发布用例、排名批次生成/冻结/发布/撤回及后继版本用例、角色范围查询和审计接口；优先暴露既有能力，不在 Blueprint 重复业务规则。
- 数据：规则草稿/来源版本/差异摘要，排名批次状态与审计字段可能需要扩展；已发布规则包、计分快照和正式排名历史不可覆盖。
- 兼容：竞赛继续走 `MaterialRecord + RuleVersion + ScoreEntry`；非竞赛旧 `Application` 页面仅保留明确标识的兼容入口，不能与新工作台混合提交或重复计分。
- 主要风险：前端隐藏按钮被误当权限控制、规则复制错误继承、排名冻结后仍被后台直接编辑、学生隐私泄露，以及旧成绩管理页继续写入派生字段。
