# Design

## Context

参见 `proposal.md`。归档 change1 的领域、数据和后端契约大部分已存在，但真实 `start-local.ps1` 环境暴露了关键断点：`prepare_local.py` 只建立 2026 demo 周期与旧测试规则，没有建立竞赛目录 API 固定查询的 2028 global current 包；`CompetitionWorkflow.vue`/`MaterialWorkflow.vue` 是未采用既有设计系统的契约壳；错误映射把规则包缺失 404 隐藏为材料错误；父子组件重复读取记录；测试未挂载页面或执行浏览器旅程。

归档工件保持只读。本 change 只纠正运行时和前端验收缺口，不修改 2028 正式政策内容，也不吸收 change2 的 2029 管理与正式排名范围。

## Goals / Non-Goals

**Goals:**

- 建立单一后端竞赛上下文，使周期、current 包和目录关系可发现、可校验且可解释阻塞。
- 让 fresh local database 与启用的竞赛入口保持一致，重复准备幂等。
- 将学生/教师竞赛页面从裸契约壳提升为沿用现有设计系统的完整交互。
- 建立可区分、可恢复的加载/空/配置/验证/冲突/权限/网络/成功状态。
- 用 mounted component、启动集成和真实浏览器证据关闭任务。

**Non-Goals:**

- 不改动竞赛目录、分值矩阵、专项聚合和证据有效期政策。
- 不实现 2029 复制编辑、排名发布或非竞赛模型迁移。
- 不重写归档 change1 工件，不用前端状态替代后端权限与状态机。

## Decisions

### 1. 增加单一竞赛上下文读取，而不是继续在页面和端点硬编码 2028

后端提供一个授权、只读的当前竞赛上下文，至少返回申报可用性、周期、current 包 ID/版本/摘要、证据区间、目录状态和稳定阻塞 code。目录、材料创建和反馈均绑定该上下文；客户端只缓存展示所需值，不自行选择年份。

若业务政策仍限定 2028，后端可以返回 2028，但这个事实由当前包与周期政策关系决定。替代方案是只在前端把 `2028` 抽成常量；它仍会与本地活动周期、未来周期和后端配置漂移，因此不采用。

### 2. 本地准备在一个受保护事务中确保竞赛依赖就绪

fresh database 建表与 demo 账号/周期完成后，准备流程调用现有正式包校验/装载能力，以内容摘要幂等确保唯一 2028 global current 包。初始化失败使准备命令失败，不能继续打印成功。重复执行只复用相同包，不清理用户后续生成的材料。

已存在但无迁移版本的旧测试库可按用户确认删除重建；不为仅含测试数据的历史 SQLite 引入猜测性列修复。生产环境仍使用正式迁移与独立装载流程，本地 seed 不能替代生产发布。

替代方案是页面启动时自动创建规则包；这会让只读请求产生管理写入并绕过发布权限，因此不采用。

### 3. 页面使用“上下文控制器 + 展示组件”而不是父子组件各自加载

竞赛路由页面拥有上下文和材料集合的读取责任，并把明确状态传给目录选择、事实表单、附件/OCR、材料卡片、反馈等展示组件。子组件只触发领域动作并通过一个刷新入口重新读取权威状态。

每个写操作维护独立 pending 状态并阻止重复点击；动作只调用一个后端命令。读取使用请求代次或取消机制，旧响应不能覆盖新选择。目录搜索采用去抖/取消，但搜索空结果与上下文失败分别建模。

替代方案是保留 `MaterialWorkflow` 和 `CompetitionWorkflow` 双重 mounted load；它已经产生重复请求且使错误/加载状态互相覆盖，因此不采用。

### 4. 以现有设计系统完成产品页面，不新增平行视觉体系

复用 `unified-system-shell`、共享 content styles、card/filter/form/button/status 语言和既有响应式断点。竞赛页面至少划分：上下文/阻塞摘要、目录搜索、材料事实、条件字段、附件与 OCR/手填、草稿/历史卡片、计分反馈。标签与控件使用稳定关联和可访问状态。

专用样式只负责竞赛表单网格和局部布局，不能以全局裸 `label/input` 选择器修补。教师审核复用只读事实/规则/候选分分区，并仅从 `allowed_actions` 提供通过/退回。

替代方案是只给当前裸元素增加若干 margin；它不能形成状态层级、窄屏顺序和可维护组件边界，因此不采用。

### 5. 错误模型保留后端 code，并为未知错误提供中性回退

API adapter 保留 HTTP status、稳定 code、后端安全 message 和 request/correlation ID。页面错误映射按配置阻塞、验证、权限、冲突、重复、附件、服务错误分类；未知错误使用“服务暂不可用/操作未确认”而不是指责材料内容。

缺包响应使用稳定 JSON code，而非仅依赖 Flask HTML/description 404。页面在缺包时显示阻塞面板并禁用表单；目录成功但 items 为空使用普通搜索空状态。

### 6. 验收采用三层证据并从 fresh environment 开始

第一层是纯函数/请求契约与后端领域测试；第二层是 Vue 真实挂载测试，模拟 API 状态并断言 DOM、交互、pending、错误恢复和单请求责任；第三层是实际 `start-local.ps1` 环境的浏览器旅程。

浏览器旅程从删除测试 SQLite 后准备环境开始，使用共享学生/教师账号完成目录选择、草稿、附件、OCR 失败或手填、提交、审核和反馈，并记录关键网络状态与截图。构建和源码搜索保留为辅助门槛，但不得命名为组件或 E2E 通过。

## Risks / Trade-offs

- [现有正式初始化工具带清理语义] → 抽取/复用只负责校验和幂等装载的安全路径，本地准备不得调用会删除材料的 reset 分支。
- [活动 demo 周期与正式 2028 包语义冲突] → 由后端显式建模两者关系并在不合法时阻塞，不由客户端任选其一。
- [页面重构可能破坏已通过的请求字段边界] → 保留 adapter/forbidden-field 测试，并在 mounted/browser 层捕获实际 payload。
- [真实 OCR 依赖不稳定] → 浏览器验收至少覆盖明确的 OCR 失败/停止后手填路径；OCR 成功路径可在可用环境单独记录，不阻塞人工闭环。
- [视觉验收主观] → 使用现有设计系统、明确断点与状态清单，并保存桌面/窄屏截图供复核。
- [纠正 change 与 change2 页面工作重叠] → 本 change 只完成竞赛申报/审核闭环；三角色规则、排名和综合工作台仍由 change2 所有。

## Migration Plan

1. 先增加上下文/阻塞契约和 fresh database 初始化集成测试，使当前 404 以失败测试固定下来。
2. 实现安全、幂等的本地正式包就绪流程及 JSON 错误契约；验证重复准备和失败退出。
3. 建立前端上下文 controller 与状态模型，消除硬编码周期和重复加载，再逐区替换学生页面裸结构。
4. 完成教师只读审核页面、错误恢复、OCR/手填和材料状态交互，保持后端命令不变。
5. 运行 mounted tests、后端回归、生产构建和 fresh database 浏览器旅程，保存证据。
6. 若回滚页面，竞赛入口保持关闭/阻塞而不是恢复旧 `Application` 竞赛写入；已创建的新链路材料和审计保留。
