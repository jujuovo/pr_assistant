# Spec Delta

## ADDED Requirements

### Requirement: 当前竞赛规则上下文由后端统一发现
系统 MUST 向授权用户返回可申报竞赛的周期、current 规则包标识、版本、摘要、证据有效期和目录可用状态；客户端不得通过硬编码自然年或本地常量选择正式规则包。

#### Scenario: 读取当前竞赛上下文
- **GIVEN** 2028 正式竞赛规则包是当前可申报包
- **WHEN** 学生、授权教师或管理员读取竞赛上下文
- **THEN** 系统返回同一个周期、包标识、版本和内容摘要，并使后续目录与材料请求引用该上下文

#### Scenario: 活动周期与正式包不一致
- **GIVEN** 系统活动周期与现有竞赛 current 包无法形成合法申报关系
- **WHEN** 客户端读取竞赛上下文或尝试创建材料
- **THEN** 系统返回稳定配置阻塞结果且不允许客户端任选一个年份继续

#### Scenario: 客户端伪造周期
- **WHEN** 客户端提交与权威竞赛上下文不一致的周期或规则包标识
- **THEN** 系统拒绝请求且不创建材料、不绑定其他包也不生成候选分

### Requirement: 正式目录不可用与搜索无结果必须区分
系统 SHALL 区分“没有 current 规则包”“规则包无效或未就绪”“正式目录成功但搜索无匹配项”，并为每种状态返回稳定 code；空数组只能表示已成功查询的目录没有匹配项。

#### Scenario: 规则包缺失
- **WHEN** 授权用户请求目录但目标上下文没有 current 规则包
- **THEN** 系统返回配置阻塞 code 与上下文信息，不返回成功的空目录

#### Scenario: 搜索无匹配项
- **GIVEN** current 规则包及目录已通过校验
- **WHEN** 搜索词没有匹配任何正式竞赛
- **THEN** 系统返回成功响应、包摘要和空 items，客户端可明确展示搜索空状态
