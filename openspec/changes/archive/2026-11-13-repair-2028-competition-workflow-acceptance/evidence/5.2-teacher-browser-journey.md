# 5.2 教师真实后端审核旅程

记录日期：2026-11-11 至 2026-11-13（Asia/Shanghai）

## 环境、角色与路由

- fresh SQLite 与正式本地后端，环境来源见 `7.1-fresh-database-readiness.md`。
- 浏览器：Microsoft Edge；全部浏览器操作由用户人工执行。
- 角色：教师 `teacher001`，不记录密码或其他秘密。
- 待审路由：`/teacher?page=pending-review`；历史路由：`/teacher?page=review-history`。

## 真实旅程

1. 教师从竞赛待审入口打开材料 #1，读取只读学生事实、固定规则包、后端候选分和图片原件。
2. 教师填写意见“请将项目名称修改为竞赛闭环验收-修正版”并执行退回；请求成功，#1 从 `submitted v3` 变为 `needs_correction v4`。数据库 `competition_returned` 事件保存该非空意见、版本、决定与幂等键。
3. 学生完成补正 #2 并重提后，教师打开 #2、核对图片并通过；#2 原子转为 `scored v5`，创建唯一 ScoreEntry #1 与 StudentScoreSnapshot #1。
4. 发现既有通过事件意见为空后，系统已修复为前后端强制非空意见；历史事件保持原样，不回写或伪造。真实挂载验证空意见会聚焦 textarea 且不发请求，后端返回稳定 `competition_review_comment_required`。
5. 教师历史入口补齐后，用户再次在 Edge 打开 #2，人工确认详情与图片可见、没有通过/退回按钮。
