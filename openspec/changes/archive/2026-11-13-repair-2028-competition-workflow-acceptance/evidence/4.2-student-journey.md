## 2026-11-13 实际浏览器 Network 请求体复验

用户在 Microsoft Edge DevTools Network 中人工检查一个可清理测试草稿的两个实际请求。

创建请求 `POST /api/materials/competition/records`：

```json
{
  "year": 2028,
  "data": {
    "competition_id": "c09-computer-design",
    "project_name": "测试草稿-请删除-20261113",
    "award_date": "2027-05-12",
    "level": "national",
    "award": "first_or_above",
    "event_year": 2027,
    "participation_mode": "individual"
  }
}
```

编辑请求 `PATCH /api/materials/competition/records/6`：

```json
{
  "version": 1,
  "data": {
    "competition_id": "c09-computer-design",
    "project_name": "测试草稿-20261113",
    "award_date": "2027-05-12",
    "level": "national",
    "award": "first_or_above",
    "event_year": 2027,
    "participation_mode": "individual"
  }
}
```

两个真实请求均不含 `rule_id`、`rule_version_id`、`candidate_score`、`self_score`、`final_score`、`override_score`、`dynamic_coefficients` 或 `allocation_policy`。Network 名称显示为 `6` 是因为编辑 URL 的最后路径段是材料 ID，并非重复或异常请求。

请求体复验后用户通过页面“删除草稿”执行正式清理；只读数据库核对确认 #6 为 `abandoned v3`，活动草稿为 0，唯一 active ScoreEntry 仍为正式补正材料 #2 的一条记录。后端归一化后的存储数据曾包含服务器生成的 `candidate_score=3.3333` 与 `allocation_policy=individual_one_third`，但它们不在上述浏览器请求体中。

原闭环后续阶段已在 `7.2-fresh-database-loop.md` 证明：教师退回、学生查看反馈、创建补正、PATCH 修改、上传与重提、教师通过及最终反馈均已完成。#6 已转为 `abandoned`，4.2 不再有运行态残留。
