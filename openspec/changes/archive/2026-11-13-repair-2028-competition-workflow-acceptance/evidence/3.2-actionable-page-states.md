# 3.2 可操作页面状态与稳定错误语义

记录日期：2026-11-11（Asia/Shanghai）

## 实现

- 页面状态区分：`loading`、`empty`、`search-empty`、`configuration`、`validation`、`permission`、`conflict`、`backend-unavailable`、`ready`。
- 配置阻塞 code（缺周期、缺包、无效包、周期不一致）显示管理员修复建议，且不渲染申报表单。
- 字段/附件/重复材料错误归入 validation；权限错误说明会话或组织权限；版本冲突要求刷新权威状态。
- 未知服务错误采用中性说明“问题不一定来自材料内容”，不再统一指责用户核对材料。
- 上下文已加载后的校验、冲突或写入服务失败保留表单与用户输入。
- 搜索成功但没有匹配项使用独立普通空状态，不与缺包或网络失败混淆。

## 真实挂载验证

```powershell
npm.cmd --prefix frontend run test:mounted
```

结果：`1 test file passed, 8 tests passed`。

挂载测试逐一触发并断言 DOM：

- 未决 Promise 显示 loading；
- 成功且无 records 显示材料 empty；
- 成功搜索空数组显示 `正式目录无匹配结果`；
- `competition_package_missing` 显示 configuration、管理员建议、无表单；
- 403 显示 permission、无表单；
- 503 显示 backend-unavailable 和中性说明、无表单；
- 空表单提交触发 validation 且表单保留；
- `version_conflict` 触发 conflict 且表单保留；
- 所有缺包场景均不含旧文案 `操作失败，请核对材料后重试`。
