# 2.1 fresh local database 正式竞赛包就绪

记录日期：2026-11-11（Asia/Shanghai）

## 实现

- `backend/tools/prepare_local.py` 从仓库正式来源 `backend/rules/competition_2028.json` 读取并校验规则包。
- fresh database 创建 2028 周期政策，以正式包证据区间 `2025-09-01` 至 `2028-08-31` 为权威日期，并把它设为唯一 active 周期。
- 通过既有 `load_current_competition_package` 用例幂等装载 `global/current` 包，不在脚本中复制发布规则。
- 装载后调用 `competition_workflow_context` 做端到端就绪检查；准备成功输出周期、包 ID/版本、目录数量和新建/复用状态。
- 第二次准备保留已存在账号密码、学生成绩和业务记录，不让 2026 demo 测试规则重新夺回 active 周期。
- 非 fresh 数据库若 active 周期与正式包周期不一致则失败，不静默切换用户已有周期。

## 验证

```powershell
.\.venv\Scripts\python.exe -B -m pytest backend/tests/test_local_prepare.py -q -p no:cacheprovider --basetemp .pytest_tmp_local_prepare_repair
```

结果：`1 passed in 27.69s`。

该测试对同一个全新 SQLite 文件连续执行两次正式准备命令，并验证：

- 三个共享账号与既有测试规则保持唯一；
- 唯一 active 周期为 2028；
- 唯一 current 竞赛包为 `2028/global/current`；
- 目录为 28 项且 `field_schema` 为对象；
- 第二次执行的规则包 digest 与第一次一致；
- 不存在其他周期的 current 包；
- 人工修改的学生成绩与账号密码在第二次准备后仍保留。
