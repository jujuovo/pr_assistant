# 3.1 竞赛页面单一请求控制器

记录日期：2026-11-11（Asia/Shanghai）

## 实现

- `MaterialWorkflow` 在类别为 `competition` 时只负责路由/类别选择，不再读取 records。
- `CompetitionWorkflow` 是学生竞赛上下文、records 与 feedback 的唯一加载所有者。
- 页面先读取权威 context，再用后端返回的 `cycle.cycle_code` 读取 records/feedback 和创建草稿。
- 显式刷新只重新读取 records/feedback，不重复加载 context。
- 目录项切换只读取对应目录 schema，不触发 records 刷新。
- 学生竞赛、教师竞赛和 `materialApi` 目标路径中不存在 `2028` 周期常量。


结果：`1 test file passed, 2 tests passed`。

挂载测试实际编译并挂载 `.vue` 组件，使用 API request spies 验证：

- 直接通过 `MaterialWorkflow` 打开 competition 时：context 1 次、records 1 次、feedback 1 次；
- 点击刷新后：records/feedback 各只增加 1 次，context 不重复；
- 切换目录项：只调用 catalog item schema，records 次数不变。
