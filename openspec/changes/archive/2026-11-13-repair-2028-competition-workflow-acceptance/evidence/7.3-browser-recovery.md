# 7.3 真实浏览器恢复场景

记录日期：2026-11-11（Asia/Shanghai）

环境：fresh local SQLite 延续的同一验收数据库；Microsoft Edge；浏览器操作全部由用户人工完成，Codex 仅切换宿主后端/数据库条件并读取日志与权威状态。

## 权限不足

- 角色：`teacher001`。
- 路由：`/student?page=materials&category=competition`。
- 观察：角色不匹配时路由守卫跳转登录页；未加载或泄露学生竞赛材料，也未提供学生写操作。

## 后端不可用与恢复

第一次停止 5001 后端后，浏览器刷新被全局认证初始化错误清会话并跳转登录，验证码也不可用。该结果不通过，随后修复：

- 通用 API 错误保留 HTTP status/code。
- 只有明确 401 或 `logged_in=false` 才清理本地会话；网络失败/5xx 保留已知角色，使业务页面展示自身错误状态。
- mounted 回归覆盖网络不可达保留角色、401 清会话、明确过期清会话。

修复后重新登录 `student001`，再次仅停止 5001 并在竞赛页 `Ctrl+F5`：页面留在竞赛路由并显示“服务暂不可用”，不再跳登录。恢复 SQLite 后端后点击“重新加载”，无需重新登录即恢复 2028 上下文、规则包、记录与 3.3333 反馈。

## 缺少 current 规则包

在确认包 #1 原状态为 `current / current_scope_key=2028:global / retired_at=null` 后，用满足数据库约束的单事务临时切换为 `retired / current_scope_key=null`。学生刷新竞赛页显示“竞赛申报暂未开放”，不显示可提交空表单，也未误报搜索无结果或材料错误。随后精确恢复原状态并成功重新加载。

## 精确重复材料

学生按已计分 #2 的完全相同事实创建草稿并上传附件。草稿阶段允许未完成材料共存；提交时后端返回 `duplicate_submission`，页面显示“相同竞赛材料已经提交”，草稿保持 draft，未新增审核命令或 ScoreEntry。用户通过正式“删除草稿”动作清理，记录保留为 abandoned 审计历史。

## 版本冲突

学生创建测试草稿 #5，在两个 Edge 标签页同时以相同版本进入编辑。标签 B 先保存 `版本冲突验收B-20261111`，记录更新为 v2；标签 A 再尝试保存 `版本冲突验收-A`，页面显示：

```text
内容已发生变化
材料已被其他操作更新，请刷新权威状态后重新确认。
```

冲突时 A 输入仍保留，没有覆盖权威值。刷新后退出编辑模式，数据库保持 B/v2；用户随后通过正式“删除草稿”动作清理。只读数据库复核确认记录 #5 保留为 `abandoned/v3` 审计历史，而不是物理删除。

- 唯一 ScoreEntry：1，仍绑定正式补正材料 #2。
- 正式规则包 #1 已恢复 `current / 2028:global / retired_at=null`。
