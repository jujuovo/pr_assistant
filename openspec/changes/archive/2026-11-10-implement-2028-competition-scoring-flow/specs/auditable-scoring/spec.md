# Spec Delta

## ADDED Requirements

### Requirement: 竞赛计分不允许客户端或教师改写
竞赛材料的规则选择、基础分、个人分和实际计入分 MUST 完全由后端基于固定规则包和学生确认事实计算；任何角色提交的 `rule_id`、`self_score`、`final_score`、`dynamic_coefficients`、`override_score` 或 `override_reason` 均不得成为权威输入。

#### Scenario: 学生伪造高分
- **WHEN** 学生提交竞赛材料时携带自评分或规则编号
- **THEN** 系统忽略展示性旧字段或以契约错误拒绝请求，并仅按权威字段匹配计算

#### Scenario: 教师尝试人工改分
- **WHEN** 教师在通过请求中提交不同分数或覆盖理由
- **THEN** 系统不得创建覆盖事实，审核计分命令失败且不保留部分状态

### Requirement: 竞赛审核与专项聚合保持单事务一致
竞赛 `approve` MUST 在一个事务中完成版本与权限校验、审核结论、资格与规则计算、计分明细、专项互斥、最高三项、学生周期快照、试算排名失效和审计；任一步失败时全部回滚。

#### Scenario: 专项聚合失败
- **WHEN** 审核结论已暂存但同作品取最高或快照重建失败
- **THEN** 系统回滚审核、明细、汇总、失效标记和审计，不向客户端报告通过成功

#### Scenario: 幂等重试通过命令
- **GIVEN** 同一材料版本和幂等键的通过命令已成功
- **WHEN** 客户端重试相同内容
- **THEN** 系统返回等价结果且不重复审核、计分或累计

### Requirement: 每项竞赛反馈同时解释候选分与实际计入分
学生和授权教师读取竞赛计分结果时，系统 SHALL 返回材料状态、规则包版本、映射依据、候选个人分、实际计入分、是否计入及稳定排除原因；计分失败或规则歧义不得伪装为成功或默认零分。

#### Scenario: 较低的同作品结果
- **WHEN** 学生查看被更高分同作品排除的有效材料
- **THEN** 系统显示其候选分、实际计入 0 和 `same_work_lower_score`

#### Scenario: 第四高项目
- **WHEN** 学生查看因最高三项限制排除的材料
- **THEN** 系统显示候选分、实际计入 0 和 `competition_top_three_limit`

#### Scenario: 计算异常
- **WHEN** 已通过材料无法唯一映射或专项政策计算失败
- **THEN** 系统返回明确阻塞状态并停止提交事务，不生成零分 `ScoreEntry`

### Requirement: 竞赛汇总保留所有有效与排除明细
竞赛周期汇总 SHALL 从当前有效 `ScoreEntry` 派生，保留计入项与被专项规则排除项，并以相同输入、规则版本和确定性排序得到相同结果；学生只能读取本人结果，教师只能读取授权范围。

#### Scenario: 撤回或补正已计分材料
- **WHEN** 有效竞赛材料进入撤回、退回补正或规则更正待确认状态
- **THEN** 系统可审计地失效旧明细并重建同学生全部竞赛选择，允许此前被排除项自动补位

#### Scenario: 学生读取他人汇总
- **WHEN** 学生请求另一学生的竞赛计分结果
- **THEN** 系统拒绝访问且不泄露材料、候选分或总分

### Requirement: 竞赛新旧路径不得双重计分
学业竞赛新提交 MUST 以 `MaterialRecord`、固定 `RuleVersion` 和 `ScoreEntry` 为唯一事实链；兼容期内旧 `Application` 流程不得为同一竞赛来源再产生有效分，其他类别可继续走旧流程直至后续迁移。

#### Scenario: 新竞赛材料提交
- **WHEN** 学生创建学业竞赛申报
- **THEN** 系统不创建以旧规则选择或前端自评分为权威的 `Application` 计分来源

#### Scenario: 其他材料类别申报
- **WHEN** 学生在兼容期提交尚未迁移的材料类别
- **THEN** 其旧流程继续可用，但不得误用竞赛规则包或计入竞赛最高三项
