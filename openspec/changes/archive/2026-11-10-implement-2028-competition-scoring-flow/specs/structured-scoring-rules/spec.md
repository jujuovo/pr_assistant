# Spec Delta

## ADDED Requirements

### Requirement: 同一推免周期只有一个当前竞赛规则包
系统 MUST 在同一推免周期和适用范围内只暴露一个当前正式竞赛规则包；规则包必须整体校验目录、映射矩阵、专项条款和日期政策后方可启用，学生提交不得跨规则包组合规则。

#### Scenario: 2028 正式规则包启用
- **GIVEN** 2028 竞赛规则包通过完整性与无歧义校验
- **WHEN** 管理员启用该规则包
- **THEN** 2028 周期的新竞赛材料只使用该包的目录和规则快照

#### Scenario: 尝试同时启用第二版本
- **GIVEN** 2028 周期已有当前竞赛规则包
- **WHEN** 管理员尝试并行启用另一个版本
- **THEN** 系统拒绝操作并保留原当前版本

### Requirement: 竞赛目录与规则映射作为不可变包发布
正式竞赛规则包 SHALL 保存原子目录条目、A+/A/A- 分类、合法字段选项、分值和专项政策的内容摘要；启用后不可原地修改，历史材料与计分继续引用原快照。

#### Scenario: 目录和矩阵不完整
- **WHEN** 规则包存在无分类目录项、无映射合法选项或重叠规则
- **THEN** 系统拒绝启用并报告具体缺口

#### Scenario: 历史规则可追溯
- **GIVEN** 材料已绑定旧规则包快照
- **WHEN** 授权用户查看历史材料
- **THEN** 系统返回当时的目录名称、分类、规则摘要和版本，不用当前版本替换

### Requirement: 当前周期规则更正要求学生重新确认
当前周期规则包更正后，系统 MUST 识别所有受影响的未完成和已审核材料；已审核结果不得静默重算，新规则只有在学生基于新快照重新确认并提交、教师重新审核后才能改变分数。

#### Scenario: 更正影响已审核材料
- **WHEN** 新规则包与材料原绑定快照的适用结果不同
- **THEN** 系统保留旧计分历史、使其退出当前有效汇总、记录失效原因并通知学生重新确认

#### Scenario: 学生未重新确认
- **GIVEN** 受影响材料尚未由学生重新确认提交
- **WHEN** 系统生成当前计分反馈
- **THEN** 系统显示待重新确认状态，不用新规则自动改分且不创建教师审核任务

#### Scenario: 通知发送失败
- **GIVEN** 规则更正的核心失效事务已提交
- **WHEN** 学生通知发送失败
- **THEN** 系统保留可重试通知任务且不回滚已记录的规则更正和材料状态
