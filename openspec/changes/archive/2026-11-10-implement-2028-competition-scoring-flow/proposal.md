# Proposal

## Why

现有竞赛申报仍混用 `Application`、前端选规则/估分和教师可改分等旧链路，无法保证附件 2 竞赛库、2028 届正式规则、审核事实与最终计分之间形成唯一且可审计的闭环。现在需要先把“学业竞赛”做成首个完整迁移样板，让学生只能申报规则内项目、教师只核验证明事实、后端自动执行全部特殊计分条款并给出可解释反馈。

## What Changes

- 预置适用于 2028 届（2025 级）的正式竞赛规则包，证据有效期为 `2025-09-01` 至 `2028-08-31`（含边界），把附件 2 中合并展示的竞赛拆成可独立选择、带稳定标识和 A+/A/A- 分类的原子项目。
- 新增完整的学业竞赛政策：国家级/省级奖项矩阵、无效选项约束、团队分配、ICPC/CCPC、CSP、同作品/同赛事取最高、最高三项及学业专长封顶，并为每个未计入项目返回稳定原因。
- 学生端改为从竞赛库搜索并单选项目；支持 OCR 后确认/修正以及停止 OCR 后手填，保存 OCR 原文与学生确认词条，要求需要排名计分的团队项目同时填写总人数和本人排序。
- 教师端只读展示原件、OCR 原文、学生确认词条、后端匹配规则和候选分，仅允许“通过”或“退回”并填写意见；关闭竞赛材料的规则选择和人工改分能力。
- 审核通过后由单一后端用例原子完成规则校验、资格判断、计分明细、去重取最高、最高三项、周期汇总与审计；失败时不保留部分审核或计分成功。
- 学生可查看每项候选分、实际计入分、排除原因和竞赛合计；退回材料可修改后重新提交或由学生放弃，后端不解析教师意见来决定能否重提。
- **BREAKING**：竞赛申报不再接受客户端权威字段 `rule_id`、`self_score`、`final_score`、`dynamic_coefficients`、`override_score`、`override_reason`；竞赛新数据只走 `MaterialRecord + RuleVersion + ScoreEntry`。现有测试数据可清空重建，其他材料类别暂时继续使用旧 `Application` 兼容流程。
- 当前周期规则被更正时保留旧快照，影响材料不得静默重算；系统通知学生重新确认/提交并由教师重新审核后，计分才可改变。
- 范围外：2029 届复制上一届并编辑规则的管理界面、其他材料类别迁移、完整三角色前端整治，以及排名生成/冻结/解冻/正式发布。

## Capabilities

### New Capabilities

- `academic-competition-scoring`: 定义附件 2 竞赛目录、正式计分矩阵、团队分配、特殊赛事规则、重复/取最高及最高三项等学业竞赛专属行为。

### Modified Capabilities

- `structured-scoring-rules`: 将单条通用规则扩展为周期内唯一生效、不可变且可审计的 2028 竞赛规则包与原子竞赛目录，并约束规则更正后的重新确认链路。
- `material-evidence-review`: 增加目录受限选择、OCR 可取消与迟到结果隔离、团队字段、精确重复阻止，以及教师仅通过/退回且不可修改事实与分数的竞赛审核流程。
- `auditable-scoring`: 增加竞赛后端唯一计分权威、禁用教师改分、专项聚合排除解释，以及审核计分事务的一致性要求。
- `recommendation-cycle-policy`: 明确 2028 届周期的竞赛证据有效日期区间及含边界语义。

## Impact

- 后端：`MaterialRecord`、`RuleVersion`、`ScoreEntry`、学生周期快照及材料/审核/计分用例；竞赛目录与正式规则包加载、校验和迁移；相关材料、证书、规则与分数 API 契约。
- 前端：学生竞赛申报和材料历史/分数反馈、OCR 停止与手填交互、教师待审核与历史详情；移除竞赛路径中的前端规则选择、估分和改分输入。
- 数据与兼容：允许删除当前测试数据并从空库建立 2028 正式规则；其他材料暂留旧路径，但不得与竞赛新路径重复入分。旧模型仅作为过渡兼容，不在本 change 物理删除。
- 审计与风险：所有材料版本、审核意见、规则快照、计分和排除理由均需留痕；规则更正、并发重试、OCR 迟到写回和新旧双计分是主要风险。正式排名发布行为不在本 change 改动范围。
