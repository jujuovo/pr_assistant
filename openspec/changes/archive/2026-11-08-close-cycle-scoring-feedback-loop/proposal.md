# Proposal

## Why

当前证书确认页把 OCR 中由学生确认的日期与申请表 `award_date` 分开提交，二者不一致时仍可保存，已造成有效期内的 2026-05-08 奖状被保存为 2026-11-12 并错误进入 `verified_not_eligible`。同时，现有规则只按周期、材料类别和学院粗粒度匹配，可能让“三等奖”误用一、二等奖或泛化的 5 分规则；无匹配规则又要等到教师审核后才暴露，模糊了学生、管理员和教师的责任。

本 change 需要把闭环前移为“学生确认结构化证据—确定性规则匹配—正式提交—教师核验—权威计分”，让没有对应规则的材料停留在学生与管理员可处理的状态，而不是进入教师审核或伪装成审核后 0 分。

## What Changes

- OCR 继续只负责辅助提取；学生确认后的结构化字段快照成为正式规则匹配和证据日期形成的唯一输入。
- 统一 OCR 原始日期、学生确认日期与规范化 `award_date` 的来源语义；申请表日期与材料确认日期冲突时阻止提交并返回稳定错误，不得静默选择。
- 建立管理员规则填写模块，以不可变版本维护“推免周期、学院、材料类别、竞赛名称、奖项等级、竞赛级别/赛区、组别或赛道 → 分值”的映射，并在发布前阻止重叠和歧义规则。
- 学生保存材料时由后端匹配唯一已发布规则。无匹配时保存为 `rule_unmatched`，只在学生“我的项目”和管理员未覆盖词条清单中显示，学生端展示 0 分、未审核及“材料词条没有对应计分”，不进入教师待审核，不生成 `ScoreEntry`，也不伪造 `StudentScoreSnapshot`。
- 管理员后来发布适用规则时，只把受影响材料标记为 `rule_available` 并通知学生确认；不得自动提交、核验或计分。学生确认规则和结构化申报信息并重新提交后，材料才进入教师审核。
- 教师只核验已匹配不可变规则版本且已正式提交的材料；对 `rule_unmatched` 或 `rule_available` 材料没有审核责任或访问入口。
- 已核验但日期录入错误的材料通过版本化补正重新确认、匹配和审核；旧核验、资格判断和修正轨迹保持追加式审计，不直接改库补分。
- 保持核验、日期资格、规则自动分、计分明细、周期快照、兼容投影和 draft 排名失效的统一事务；三等奖不得命中一、二等奖或仅按 `competition` 分类的默认规则。
- 范围外：排名算法和排名运营页重写、志愿工时学生页面、通用 OCR 扩展、旧表/旧字段物理删除、全站视觉重构和微服务拆分。

## Capabilities

### New Capabilities

- `recommendation-cycle-policy`: 定义全局唯一活动推免周期、周期级奖状有效日期区间、申请周期固定、日期权威来源、历史政策留存与日期资格判断。
- `structured-scoring-rules`: 定义结构化材料词条到分值的不可变版本映射、确定性匹配、发布歧义门禁、未覆盖词条管理和规则补齐后的学生再确认。

### Modified Capabilities

- `material-evidence-review`: 将学生确认的结构化证据快照、日期冲突、规则覆盖前置状态、教师职责边界和版本化补正纳入材料生命周期。
- `auditable-scoring`: 将提交前规则匹配、无规则材料的非审核 0 分解释、已固定规则版本审核计分、日期补正重审和学生单项/总分反馈纳入权威计分契约。

## Impact

- 后端：证书预览确认、`Application`/`MaterialRecord` 兼容边界、结构化词条快照、规则/规则版本、提交与审核用例、`ScoreEntry`、`StudentScoreSnapshot`、历史补正和对账工具。
- API：证书确认、规则预匹配、规则发布预检、未覆盖词条、学生重新提交、教师待审核和学生当前周期解释契约将增加稳定状态、原因码和 `allowed_actions`。
- 前端：学生确认页以结构化字段为准并处理日期冲突；“我的项目”展示 `rule_unmatched/rule_available`；管理员获得规则填写及未覆盖词条入口；教师列表排除未匹配或未重提材料。
- 数据与审计：新增或扩展结构化快照、规则匹配结果、状态事件和补正版本；旧 OCR 原文、旧审核和错误资格结果不得被覆盖删除。
- 兼容与发布：采用非破坏迁移并保留旧投影；受影响历史对象完成分类和验收前不归档本 change，不允许对账未清零范围进入正式排名发布。SQLite 结果不能替代目标 PostgreSQL 的迁移、约束和并发验证。
