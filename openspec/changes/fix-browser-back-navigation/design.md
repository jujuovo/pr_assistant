# Design

## Context

三角色页面都在单一顶层路由下通过 `route.query.page` 切换子页面。当前用户点击侧边栏或分类入口时使用 `router.replace` 覆盖当前历史记录；登录成功使用 `router.push` 进入角色首页。浏览器历史因此只剩登录页和当前页，后退键回到登录页。

## Goals / Non-Goals

**Goals:**
- 让用户在业务页之间使用浏览器后退时回到上一个业务页。
- 登录页不再留在角色端历史中。
- 不改变页面结构、接口和业务状态。

**Non-Goals:**
- 不引入嵌套路由或重写路由结构。
- 不改变显式“返回”按钮的业务语义。
- 不修改未登录重定向和注销行为。

## Decisions

### 1. 主动前进导航使用 `push`

侧边栏 `switchPage`、分类进入材料页、个人信息、编辑申请、“我的材料”等用户主动跳转改用 `router.push`。每次跳转新增历史记录，浏览器后退自然回到上一业务页。

替代方案是继续使用 `replace` 并自行维护历史栈；会重复 Vue Router 的能力，容易遗漏。

### 2. 登录成功使用 `replace`

登录成功后用 `router.replace` 进入角色首页，移除登录页历史。这样从角色首页后退不会回到登录页；需要退出时使用注销按钮。

### 3. 清理、注销和重定向保留 `replace`

以下场景继续使用替换，不产生额外历史：

- 取消编辑后清理 `editId`；
- 注销后进入登录页；
- 未登录或角色不匹配的守卫重定向；
- 显式“返回上一逻辑页”的页内按钮。

### 4. 重复点击当前页不新增历史

布局的 `switchPage` 在目标页面等于当前页面时直接返回，避免侧边栏重复点击堆积历史记录。

## Risks / Trade-offs

- [主动导航产生更多历史记录] → 只在页面实际变化时 push，并跳过当前页重复点击。
- [显式返回按钮与浏览器后退语义不同] → 显式返回仍是页内逻辑返回，使用 replace；浏览器后退用于跨页面历史。
- [深链接直接进入业务页时后退可能离开系统] → 这是浏览器正常行为；系统内导航从角色首页开始时会保留完整历史。

## Migration Plan

- 仅前端行为改动，无数据库或接口迁移。
- 回滚时恢复相关 `router.push`/`router.replace` 调用即可。
