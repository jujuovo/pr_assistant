## 相关技术开源

### OCR

OCR 是“光学字符识别”(Optical Character Recognition)。它能把图片、扫描件或 PDF 里的文字识别出来，转换成可复制、搜索和编辑的文本。

 - **[PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR)**：核心 OCR，优先推荐。 提供中文 OCR、方向处理、文字框和识别分数；PP-Structure 可进一步解析版面、表格和印章文字。适合建立“字段→原图区域”的证据链，支持 CPU/GPU 部署。代码采用 Apache-2.0。实际证书中的艺术字体、反光和盖章遮挡仍需专项评测。

 - **[PaddlePaddle/PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR)** 百度开源、中文识别最强、可本地部署、免费商用。更重要的是它是一个"全家桶"，自带你要的三件套：
    - **PP-Structure**：版面分析（把证书拆成"标题/正文/落款/表格"区块）
    - **KIE（关键信息抽取）**：从文档里抽字段，正是你"抽比赛名/等级/主办单位"要的
    - **PaddleOCR-VL**：多模态文档理解，能直接"看图回答问题/填表"

### Qwen3-VL
```
PaddleOCR：重点是文字检测、文字识别、坐标和OCR置信度
Qwen3-VL：重点是图片理解、字段关系分析和复杂信息抽取
```

- **[Qwen3-VL](https://github.com/QwenLM/Qwen3-VL)：复杂页面的补充识别与复核。** 官方提供 OCR 和关键信息抽取示例，适合结合证书图像理解不规则排版。建议用于主流程无法可靠处理的页面；输出仍需验证原文依据、字段格式和空值，不能承担证书验真。仓库代码及已核实的 8B-Instruct 权重采用 Apache-2.0。[官方模型卡](https://huggingface.co/Qwen/Qwen3-VL-8B-Instruct)

### 印章检测

"是否是官方证明"，工程上主要靠**检测有没有红章 + 落款单位**。这两个是专门做印章识别的：

- [NephrenCake/SealOcr](https://github.com/NephrenCake/SealOcr) — 复杂环境下的各种常见印章识别（圆形章、椭圆章、方形章等），适合判断证书上是否有公章、并识别章里的单位文字。
- [KirillYd/stamp_recognition](https://github.com/KirillYd/stamp_recognition) — 印章检测识别（偏检测定位）。

### 其他

-  **[Docling](https://github.com/docling-project/docling)：多格式、多页材料解析。** 可统一处理 PDF、图像、Office 文档，输出结构化文档、JSON 或 Markdown。适合获奖公示、竞赛通知和证明附件；中文 OCR 需要配置合适的识别引擎。代码为 MIT，所用模型许可单独核对。

 -  **[MinerU](https://github.com/opendatalab/MinerU)：复杂长 PDF 的另一候选。** 适合解析论文、获奖名单、通知中的版面和表格。若首版主要是单张证书，可以后续再引入。当前许可证为带附加条件的 MinerU Open Source License，选型时应核对在线服务等条款，不能沿用旧版本的许可印象。[当前许可证](https://github.com/opendatalab/MinerU/blob/master/LICENSE.md)

-  **[ZEN Engine](https://github.com/gorules/zen)：规则执行工具。** 提供 JSON 决策规则和 Python、Node.js 等绑定，适合表达“年度、学院、赛事、赛段、奖项→建议分值”。采用 MIT。它不自带高校赛事目录和推免细则；首版规则较少时，数据库规则表加普通业务代码更直接。

-  **[pyHanko](https://github.com/MatthiasValvekens/pyHanko)：PDF 数字签名核验。** 可检查签名完整性、证书信任链及相关验证信息，采用 MIT。适用于带数字签名的 PDF，需要配置可信发证方并验证实际格式兼容性；普通扫描件中的红章图片不属于这类验签对象。[官方验证文档](https://docs.pyhanko.eu/en/latest/lib-guide/validation/general-api.html)

-  **[Label Studio](https://github.com/HumanSignal/label-studio)：标注与改进模型。** 可标注文字区域、修正 OCR、标记材料类别和字段，社区版代码为 Apache-2.0。适合积累训练数据；正式业务中的复核权限、审批和留痕仍需自己实现，部分审核功能属于企业版。[版本差异](https://labelstud.io/guide/label_studio_compare)

-  **[PaddleNLP UIE](https://github.com/PaddlePaddle/PaddleNLP/tree/develop/slm/model_zoo/uie)：中文字段抽取基线。** 可以按 schema 抽取姓名、赛事、主办方、奖项和日期，官方已有“竞赛名称—主办方/承办方”的关系抽取示例，并提供标注、微调和评估流程。纯文本 UIE 需要你自行把抽取位置映射回 OCR 文字框。代码为 Apache-2.0，模型权重应另核对具体许可。

# 解决方案

材料识别、真实性核验和加分计算是三个不同的问题。OCR 只能读取文件中的文字与版式；官方记录、数字签名或校内数据库才能增强真实性判断；

推荐方案以“可信数据来源优先”为原则。校内系统已经保存的记录采用确定性匹配；**目录内常见项目采用自动辅助；目录外材料保留人工判断。**三条通道最终均进入规则引擎和教师审核。

加分项目分类：
1. 社会实践、学生工作、荣誉称号、志愿时长等：通过学工系统或七彩信息验证；
2. 常见项目目录：自动核算分数辅助+教师确认
3. 目录外项目：非常见项目采用全人工核验方案

官方核验方式应按项目逐项配置：有授权接口时调用接口；有公开获奖名单时导入或查询名单；有查询网页、二维码或数字签名时提供受控适配器；需要验证码、登录或人工判断的渠道只保存官方入口并交由教师查询。系统应输出“官方记录一致、部分一致、字段冲突、未查到记录、通道不可用、需要人工核验”等状态，而非直接输出真假结论。
