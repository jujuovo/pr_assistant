# 单次上传与后台识别流程（2026-11-19）

本文件替代前期整合版本“先OCR再自动填表、保存后再次上传”的学生交互方案。用户手动验收提出问题后进行纠正，不代表其他三角色页面已完成验收。

## 学生操作

1. “提交材料”选择正式竞赛，手动填写项目、日期、等级、奖项及团队条件，界面显示中文，发送原有枚举值。
2. 可先点击“预估分数”，后端读取当前正式规则，只计算候选分、不创建材料。修改字段后旧预估作废，迟到响应不覆盖新输入。
3. 原件只选择一次；保存时字段、原件、适配图片的OCR队列同事务落库。返回成功即可离开或继续下一项，不等待模型。
4. “我的材料”只展示历史与管理操作，不嵌入新建表单。后台任务由工作进程处理；页面每5秒仅查询当前可见的未完成任务，离开页面不取消任务。支持状态筛选、分页、原件及OCR结果、编辑、删除、撤回、补正和规则更新确认。
5. 识别完成后标记“待提交”，学生查看预估及差异后显式“正式提交审核”。识别失败显示可重试或转人工，未适配或PDF不创建无用OCR任务。

状态为后端只读投影：草稿、OCR队列中、OCR识别中、待提交、待审核、已通过、已驳回、已退回待补正、识别异常、规则更新等；不把“退回补正”伪装为永久驳回。

## 识别与计分边界

- OCR不修改手填事实。申报预估沿用正式规则；OCR建议分基于识别到的奖项/项目以及仍需确认的申报条件。
- “条件性建议分”允许沿用未识别的级别与团队条件，但同时列出缺失依据；不表示这些条件已核验。原始总成绩不会推算CSP排名百分位。
- 只有正式目录内已适配赛事图片自动排队：蓝桥杯、计算机设计大赛、挑战杯创业计划、CSP。PDF及其余项目保留人工通道；目录外材料不自动计分、不显示自动置信度。其他原有识别接口保留，但不再挂接自动填表向导。
- `OCR_MATURE_EVENT_FAMILIES` 为后端成熟适配器开关，当前默认空。需样本验收后显式启用；无论开启与否都保留教师审核。该开关不等同于已有OCR适配器清单。
- 教师查看原件、OCR、手填事实、申报候选分和条件建议。有OCR不确定性时，必须勾选人工确认；后端也要求 `ocr_confirmed=true`。审核事件保存原始OCR、评分评估和确认记录。审核通过后仍由正式规则写唯一ScoreEntry，OCR不得直接写分数。
- 原件SHA校验、权限、版本隔离、租约、防止重复计分与迟到结果保护继续有效。编辑使旧识别作废，但不解除原件校验。

## 接口变更

| 接口 | 行为 |
|---|---|
| POST /api/materials/competition/estimate | 只读手填候选分预估 |
| POST /api/materials/competition/records（multipart） | year、JSON字符串data、files；保存一次并自动排队 |
| PATCH /api/materials/competition/records/{id}（multipart） | version、data、可选新附件；修改与原件同事务，重新版本绑定 |
| GET /api/materials/{category}/records | 读取workflow_state及ocr_assessment；保留原类别权限和分页 |
| POST /api/materials/competition/records/{id}/review | 原4字段，增加可选布尔ocr_confirmed；不接受手写分数 |
